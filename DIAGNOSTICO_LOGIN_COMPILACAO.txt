3. MOTIVO DO ENTER ID NÃO FUNCIONAR

A função configured() exige simultaneamente estas três variáveis:
- ENTRA_TENANT_ID
- ENTRA_CLIENT_ID
- ENTRA_CLIENT_SECRET

Se qualquer uma estiver vazia, /api/auth/entra/login bloqueia antes de redirecionar para a Microsoft e retorna HTTP 503. Portanto, o problema atual não é senha, banco ou botão do frontend: o backend não tem a configuração mínima do App Registration.

Depois dessa etapa, ainda é necessário validar o callback e as permissões do Microsoft Graph. O código usa:
- redirect_uri exatamente igual a ENTRA_REDIRECT_URI;
- escopos definidos em ENTRA_SCOPES;
- Microsoft Graph /me com dados de perfil e signInActivity;
- Microsoft Graph /me/memberOf para grupos;
- cookie entra_oauth_state para proteção state;
- cookie wayon_session_id para a sessão da aplicação.

4. PASSO A PASSO PARA HABILITAR ENTER ID

1) No Microsoft Entra admin center, abra App registrations e selecione o App Registration utilizado pelo SIGAC.
2) Em Overview, copie o Directory (tenant) ID e o Application (client) ID.
3) Em Certificates & secrets, crie um Client secret. Copie o valor imediatamente; ele não é exibido novamente.
4) Em Authentication, adicione uma Web redirect URI exatamente igual ao valor de ENTRA_REDIRECT_URI. Não use uma URL diferente, barra final diferente, HTTP em vez de HTTPS ou domínio diferente.
5) Confirme que a URL pública aponta para o backend, por exemplo: https://api.seudominio.com/api/auth/entra/callback. Em desenvolvimento, use a URL local do backend correspondente ao fluxo executado.
6) Em API permissions, adicione Microsoft Graph delegado User.Read. Para os dados utilizados pelo sistema, revise também GroupMember.Read.All e AuditLog.Read.All conforme a política do tenant. Conceda admin consent quando exigido pela organização.
7) No ambiente do backend, configure sem aspas extras e sem espaços:
   ENTRA_TENANT_ID=ID_DO_DIRECTORY
   ENTRA_CLIENT_ID=ID_DA_APLICACAO
   ENTRA_CLIENT_SECRET=VALOR_DO_SECRET
   ENTRA_REDIRECT_URI=URL_EXATA_DO_CALLBACK
   ENTRA_SCOPES=openid profile email User.Read
8) Reinicie o backend após alterar as variáveis. Não coloque o client secret no frontend, em NEXT_PUBLIC_* ou no repositório.
9) Abra /api/auth/entra/login. O esperado é HTTP 302 para login.microsoftonline.com; HTTP 503 ainda indica configuração ausente.
10) Após autenticar, o callback deve retornar para /dashboard. Se aparecer HTTP 400, confira state/cookies e domínio. Se aparecer HTTP 502, confira secret, redirect URI, escopos e permissões Graph. Se aparecer HTTP 401 após a Microsoft autenticar, o e-mail do Entra não está cadastrado na tabela users.
11) Cadastre o mesmo e-mail retornado por mail ou userPrincipalName na tabela users antes de testar o acesso completo.

5. LOGIN POR E-MAIL

O fallback funciona sem Microsoft Entra ID. Na tela /login, informe um e-mail existente na tabela users e use "Entrar com e-mail". O backend consulta users por e-mail sem diferenciar maiúsculas/minúsculas, cria um registro em sessions por 8 horas e envia o cookie wayon_session_id.

Esse modo não consulta Microsoft Graph e, por isso, não obtém grupos, signInActivity ou foto do Graph. Ele deve ser tratado como acesso alternativo conforme a regra de negócio definida.

- FastAPI/Starlette emite avisos deprecados relacionados a on_event e TestClient/httpx. Podem ser migrados posteriormente sem alterar o contrato da API.
