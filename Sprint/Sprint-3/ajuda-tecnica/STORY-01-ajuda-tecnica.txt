====================================================================================
  STORY-01  -  Login SSO integrado ao CAV4 (validação de token no back-end)
  AJUDA TÉCNICA / REFINAMENTO
====================================================================================
Trilha.....: Back-end
Objetivo...: Fluxo OIDC/SSO completo (start -> callback -> troca de código ->
             validação de assinatura/claims -> extração da identidade -> sessão).

------------------------------------------------------------------------------------
1) ONDE MEXER NO CÓDIGO (arquivos existentes)
------------------------------------------------------------------------------------
- back-end/app/api/routes/cav4_auth.py
    Rotas do fluxo. Já existem os endpoints:
      GET  /api/auth/cav4/start     -> monta authorization URL (state + nonce)
      GET  /api/auth/cav4/callback  -> recebe code, troca por token, cria sessão
      POST /api/auth/login          -> login manual por e-mail (mantido)
      GET  /api/auth/session        -> retorna sessão atual
      POST /api/auth/logout         -> encerra sessão
    -> REFINAR: garantir validação de issuer/audience/exp e nonce no callback.

- back-end/app/core/cav4.py
    Cliente CAV4/OIDC: discovery, troca de código, validação de token.
    -> REFINAR: separar erros (discovery, TLS, timeout, assinatura) em exceções
       específicas para gerar mensagens claras (ver critério de aceite de erro).
    -> Extrair identificador (matrícula/e-mail) e normalizar (lower/trim) AQUI,
       num único ponto, antes de consultar o banco.

- back-end/app/core/config.py
    Settings do CAV4 (client_id, client_secret, issuer/discovery URL,
    redirect_uri, CA_SSL_VERIFY, caminho do CA). Confirmar que tudo vem de env.

- back-end/app/core/temporary_sessions.py  +  app/core/authorization.py
    Emissão do cookie de sessão HttpOnly. NÃO retornar access_token ao front.

- back-end/app/core/exceptions.py
    Adicionar/normalizar exceções (Cav4DiscoveryError, Cav4TlsError,
    Cav4TokenInvalid, UsuarioNaoCadastrado) mapeadas para HTTP (403/502).
