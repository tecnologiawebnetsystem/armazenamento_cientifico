====================================================================================
  STORY-06  -  Menu e ações condicionados ao perfil (RBAC na UI) (Front)
  AJUDA TÉCNICA / REFINAMENTO
====================================================================================
Trilha.....: Front-end
Pontuação..: 3
Depende de.: STORY-03 (autorização no servidor), STORY-08 (RBAC no banco)
Habilita...: -
Objetivo...: Renderizar menu, telas e ações conforme o perfil/permissões do
             usuário logado, sem nada fixo (hardcoded) em tela.

------------------------------------------------------------------------------------
1) ONDE MEXER NO CÓDIGO (arquivos existentes)
------------------------------------------------------------------------------------
- lib/nav-config.ts
    -> Anotar cada item com a permissão exigida (ex.: requiredPermission: "logs.read").
- components/layout/app-sidebar.tsx
    -> Filtrar itens do menu pelas permissões de use-permissions.
- hooks/use-permissions.ts
    -> Expor helper can(permission: string): boolean.
- components/shared/permission-guard.tsx
    -> Envolver seções/ações restritas (ocultar/desabilitar).
- components/shared/action-button.tsx
    -> Aceitar requiredPermission e desabilitar quando não permitido.
- app/forbidden/page.tsx
    -> Página 403 do front para acesso direto por URL não permitida.

------------------------------------------------------------------------------------
2) O QUE CRIAR (se necessário)
------------------------------------------------------------------------------------
- Wrapper de rota (em app/(app)/layout.tsx ou por página) que verifica a
  permissão da rota e redireciona a /forbidden quando negado.
- Constantes de permissão em lib/permissions.ts (evitar strings soltas).

------------------------------------------------------------------------------------
3) EXEMPLO DE CÓDIGO
------------------------------------------------------------------------------------
    const { can } = usePermissions()
    {can("projects.write") && <ActionButton requiredPermission="projects.write">Novo</ActionButton>}
    // sidebar:
    items.filter(i => !i.requiredPermission || can(i.requiredPermission))

------------------------------------------------------------------------------------
4) BANCO DE DADOS
------------------------------------------------------------------------------------
- Nenhuma alteração direta. Consome a consulta de permissões (STORY-07/08) via
  endpoint que devolve perfil + permissões efetivas.

------------------------------------------------------------------------------------
5) COMO VALIDAR
------------------------------------------------------------------------------------
- Logar como Auditor -> só Logs/Relatórios em leitura; sem botões de escrita.
- Logar como Gerente -> vê gestão de projetos.
- Acessar por URL rota não permitida -> cai em /forbidden.
- Conferir no Network que as permissões vêm da API (não fixas).
