================================================================================
PLATAFORMA DE ARMAZENAMENTO CIENTÍFICO — PERFIS E PERMISSÕES
================================================================================
Documento gerado a partir do comportamento real implementado no código
(lib/types.ts, lib/mock-data.ts, hooks/use-permissions.ts, lib/nav-config.ts
e guardas de acesso em app/**/page.tsx e app/api/**/route.ts).

Este documento descreve, para cada papel, quais páginas ele acessa e o que
pode ou não fazer em cada uma. Vale a data desta geração: 16/08/2026.

--------------------------------------------------------------------------------
1. MODELO DE PERMISSÕES (DOIS NÍVEIS)
--------------------------------------------------------------------------------

A plataforma combina dois níveis de controle de acesso:

1.1. PAPEL GLOBAL DO USUÁRIO (User.role)
   Definido pelo administrador em Administração > Usuários. Controla o que o
   usuário pode fazer NA PLATAFORMA COMO UM TODO (ex.: criar projetos, ver
   páginas administrativas). É o valor usado nas guardas de rota e na
   Matriz de Permissões.
   Valores possíveis: admin | gestor | participante | visualizador

1.2. PAPEL DO USUÁRIO DENTRO DE UM PROJETO (ProjectMember.papel)
   Definido quando o usuário é adicionado como membro de um projeto
   específico (aba "Membros e Permissões" do projeto). Usa os mesmos quatro
   valores do papel global, mas se aplica somente àquele projeto — um
   usuário pode ser "gestor" no Projeto A e "participante" no Projeto B.

1.3. COMPARTILHAMENTO POR ARQUIVO/PASTA (ShareEntry.nivel)
   Ajuste fino, aplicado por item dentro do Explorador de Arquivos.
   Valores: leitura ("Somente leitura") | edicao ("Pode editar") |
   proprietario ("Proprietário").
   Regra implementada em hooks/use-permissions.ts (canEditFile):
     - papel do projeto = admin OU gestor  → pode editar o arquivo/pasta,
       independente do compartilhamento individual.
     - papel do projeto = visualizador     → nunca pode editar, mesmo que
       tenha recebido compartilhamento de "edição" ou "proprietário".
     - papel do projeto = participante     → depende do compartilhamento:
       sem compartilhamento definido = pode editar (padrão liberal);
       com compartilhamento "leitura" = não pode editar;
       com compartilhamento "edicao" ou "proprietario" = pode editar.

Em resumo: o papel do projeto é a regra principal; o compartilhamento por
item só tem poder de RESTRINGIR ainda mais um participante, nunca de
liberar algo que o papel do projeto já proíbe (caso do visualizador).

--------------------------------------------------------------------------------
2. MATRIZ DE ALÇADAS PADRÃO (Administração > Matriz de Permissões)
--------------------------------------------------------------------------------
Valores padrão definidos em lib/mock-data.ts (defaultPermissionMatrix) e
editáveis por um administrador em Administração > Matriz de Permissões
(app/api/permissions/route.ts, somente admin pode alterar).

                          admin   gestor  participante  visualizador
Ver projetos               sim     sim        sim           sim
Criar projetos              sim     sim        não           não
Editar projeto               sim     sim        não           não
Excluir projeto               sim     não        não           não
Gerenciar membros              sim     sim        não           não
Enviar arquivos                 sim     sim        sim           não
Excluir arquivos                sim     sim        não           não
Compartilhar arquivos            sim     sim        sim           não
Aprovar solicitações de acesso    sim     não        não           não

Estes valores alimentam tanto a UI (botões habilitados/desabilitados) quanto
as rotas de API (bloqueio no backend, não apenas no front).

--------------------------------------------------------------------------------
3. PÁGINAS DO SISTEMA
--------------------------------------------------------------------------------

3.1. DASHBOARD (/dashboard)
   Para que serve: visão geral com KPIs (projetos ativos, armazenamento
   usado, membros envolvidos), lista de projetos recentes e um painel que
   varia por papel.
   Acesso: todos os papéis autenticados.
   Diferença por papel:
     - admin: vê card "Solicitações de acesso" com a fila de pedidos
       pendentes de toda a plataforma (contagem em tempo real).
     - gestor / participante / visualizador: não veem o painel de
       solicitações administrativas; o dashboard mostra apenas os projetos
       em que são membros.

3.2. PROJETOS (/projetos)
   Para que serve: listagem de todos os projetos científicos com filtros por
   status e área.
   Acesso: todos os papéis autenticados (verProjetos = true para todos).
   Ações por papel:
     - admin, gestor: veem o botão "Novo projeto" (criarProjetos = true) e
       podem abrir qualquer projeto, mesmo sem ser membro.
     - participante, visualizador: não veem o botão de criar projeto;
       só acessam a página de detalhe de projetos onde já são membros —
       se tentarem abrir um projeto sem vínculo, são redirecionados de
       volta para /projetos (app/(app)/projetos/[id]/page.tsx).

3.3. NOVO PROJETO (/projetos/novo)
   Para que serve: formulário de cadastro de projeto (nome, área
   responsável, gestor, descrição, participantes iniciais).
   Acesso: somente quem tem criarProjetos = true na matriz (admin e gestor
   por padrão). Qualquer outro papel que acessar a URL diretamente é
   redirecionado para /projetos.

3.4. DETALHE DO PROJETO (/projetos/[id]) — abas Arquivos / Membros e
     Permissões / Informações
   Para que serve: hub do projeto com três abas.
   Acesso: exige ser membro do projeto OU ser admin da plataforma
   (admin ignora a exigência de vínculo, participantes.includes(user.id) é
   verificado para os demais); se não, redireciona para /projetos.

   Aba "Arquivos" (Explorador de Arquivos):
     - Todos os membros podem navegar em pastas, buscar e visualizar
       (Visualizar/preview) itens compartilhados com eles ou dentro do que
       seu papel permite.
     - canWriteFiles = admin da plataforma OU uploadArquivos=true no papel
       do projeto → controla se os botões "Nova pasta" e "Enviar arquivos"
       aparecem.
     - Menu de contexto (botão direito) por item: Visualizar, Baixar,
       Renomear, Mover, Compartilhar, Excluir — cada ação de escrita é
       condicionada por canEditFile (ver seção 1.3); "Excluir" também exige
       excluirArquivos = true no papel do projeto (ou ser admin).
     - Compartilhar item: exige compartilharArquivos = true no papel do
       projeto (ou ser admin); define o nível (leitura/edição/proprietário)
       por membro do projeto.
     - Visualizador: nunca vê os botões de escrita; pode apenas abrir
       preview e baixar itens aos quais tem acesso de leitura.

   Aba "Membros e Permissões":
     - Lista os membros do projeto e seu papel dentro dele.
     - Adicionar/remover membro ou alterar o papel de um membro dentro do
       projeto exige gerenciarMembros = true no papel GLOBAL do usuário
       logado OU ser gestor daquele projeto especificamente
       (app/api/projects/[id]/members/route.ts: role === "admin" ||
       projectRole === "gestor").
     - Participante e visualizador só visualizam a lista, sem controles de
       edição.

   Aba "Informações":
     - Dados gerais do projeto (descrição, datas, status, área).
     - Editar essas informações exige papel global admin OU papel "gestor"
       dentro do projeto (app/api/projects/[id]/route.ts).
     - Excluir o projeto é exclusivo do papel global admin
       (canDelete = user.role === "admin").

3.5. MEU PERFIL (/perfil)
   Para que serve: dados do usuário logado (nome, e-mail, cargo, área,
   papel) e edição de dados de contato; lista "Meus projetos".
   Acesso: qualquer usuário autenticado, para ver e editar apenas o próprio
   perfil.

3.6. SOLICITAR ACESSO (/solicitar-acesso)
   Para que serve: qualquer usuário autenticado pode solicitar acesso a um
   projeto (tipo de solicitação, papel desejado, justificativa e número de
   chamado ServiceNow); mostra o histórico das próprias solicitações e seus
   status (pendente/aprovado/negado).
   Acesso: todos os papéis autenticados. Cada usuário só vê e cria
   solicitações em seu próprio nome — não há campo para solicitar em nome
   de outra pessoa.

3.7. ADMINISTRAÇÃO > USUÁRIOS (/administracao/usuarios)
   Para que serve: tabela de todos os usuários da plataforma, com busca e
   edição do papel GLOBAL de cada um.
   Acesso: somente admin. Qualquer outro papel que tente acessar a URL é
   redirecionado para /dashboard (guarda de página) e a API também rejeita
   a alteração de papel para quem não é admin
   (app/api/users/[id]/route.ts).

3.8. ADMINISTRAÇÃO > FILA DE SOLICITAÇÕES (/administracao/solicitacoes)
   Para que serve: fila de solicitações de acesso pendentes de todos os
   usuários, com ações de aprovar ou negar, e histórico de solicitações já
   analisadas.
   Acesso: somente admin (aprovarSolicitacoes = true apenas para admin na
   matriz padrão; página e API bloqueiam qualquer outro papel).

3.9. ADMINISTRAÇÃO > MATRIZ DE PERMISSÕES (/administracao/permissoes)
   Para que serve: edição da matriz de alçadas descrita na seção 2 — o que
   cada papel pode fazer por padrão na plataforma (tabela papel × permissão
   booleana).
   Acesso: somente admin, tanto na página quanto na API
   (app/api/permissions/route.ts). Alterações aqui mudam imediatamente o
   comportamento de todas as páginas e rotas que consultam
   getRolePermissions().

3.10. ADMINISTRAÇÃO > PARÂMETROS (/administracao/parametros)
   Para que serve: configurações gerais da plataforma — lista de áreas
   organizacionais (CRUD), cota padrão de armazenamento por projeto (MB),
   dias de expiração de solicitações de acesso pendentes e a mensagem de
   aviso de ambiente exibida no topo do sistema (ex.: "Ambiente local ·
   dados de demonstração").
   Acesso: somente admin, tanto na página quanto na API
   (app/api/settings/route.ts).

3.11. ADMINISTRAÇÃO > TRILHA DE AUDITORIA (/administracao/logs)
   Para que serve: histórico de ações relevantes realizadas na plataforma
   (login/logout, criação/edição/exclusão de projeto, gestão de membros,
   ações no explorador de arquivos, solicitações de acesso, alteração de
   papel de usuário, alteração da matriz de permissões e dos parâmetros),
   com filtros por usuário, tipo de ação e período.
   Acesso: somente admin, tanto na página quanto na API
   (app/api/activity-logs/route.ts).

--------------------------------------------------------------------------------
4. RESUMO POR PAPEL
--------------------------------------------------------------------------------

ADMIN
   - Acessa todas as páginas, incluindo todo o grupo "Administração" no
     menu lateral (filtrado por lib/nav-config.ts, roles: ["admin"]).
   - Único papel que pode: excluir projetos, aprovar/negar solicitações de
     acesso, gerenciar usuários e seus papéis globais, editar a matriz de
     permissões e os parâmetros da plataforma, e consultar a trilha de
     auditoria.
   - Dentro de qualquer projeto, tem as permissões máximas mesmo sem ser
     membro cadastrado (bypass de verificação de vínculo).

GESTOR
   - Acesso: Dashboard, Projetos, Novo Projeto, detalhe de projetos onde é
     membro, Meu Perfil, Solicitar Acesso. Não vê o grupo "Administração".
   - Pode criar e editar projetos, gerenciar membros e permissões dentro
     dos projetos em que atua como gestor, enviar/excluir/compartilhar
     arquivos.
   - Não pode excluir projetos nem aprovar solicitações de acesso de
     outros usuários — precisa de um admin para isso.

PARTICIPANTE
   - Acesso: Dashboard, Projetos (somente os que já é membro), Meu Perfil,
     Solicitar Acesso. Não vê "Novo projeto" nem o grupo "Administração".
   - Pode enviar arquivos e compartilhar itens dentro dos projetos em que
     participa, mas não pode criar/editar/excluir o projeto em si, nem
     excluir arquivos, nem gerenciar outros membros.
   - Se solicitar mais acesso ou outro papel, deve usar a página
     "Solicitar acesso" e aguardar aprovação de um admin.

VISUALIZADOR
   - Acesso: Dashboard, Projetos (somente os que já é membro, em modo
     somente leitura), Meu Perfil, Solicitar Acesso.
   - Não pode enviar, excluir, mover, renomear ou compartilhar arquivos —
     mesmo que um compartilhamento individual de "edição" tenha sido
     concedido a ele por engano, a regra de papel do projeto prevalece e
     bloqueia a escrita (ver seção 1.3).
   - Uso típico: auditores ou stakeholders que só precisam consultar dados
     e solicitar acesso adicional quando necessário.

--------------------------------------------------------------------------------
5. OBSERVAÇÕES
--------------------------------------------------------------------------------
- Todas as guardas de acesso existem em dois lugares: na página (Server
  Component, redirecionamento) e na API (app/api/**/route.ts, resposta 403).
  Isso significa que mesmo alterando a URL diretamente ou chamando a API
  por fora da UI, as mesmas regras se aplicam.
- Este documento reflete o código na data de geração. Caso a matriz de
  permissões padrão seja alterada em Administração > Matriz de Permissões,
  os valores da seção 2 e os resumos da seção 4 passam a refletir apenas o
  comportamento PADRÃO de fábrica, não o estado atual configurado — para o
  estado atual, consulte a própria tela da matriz.
